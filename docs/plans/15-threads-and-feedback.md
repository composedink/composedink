### Task 1 — Add authority-owned thread state and live anchors

- [ ] Write offline model tests first for opening/replying/resolving, stale-base quotes, concurrent typing, edge insertion, partial deletion, complete deletion, reload and concurrent message merges. Run `mise exec -- vp run @composedink/core#test`.
- [ ] Add exactly `threads` and `requests` to `model/keys.ts`; no separate answers, comments or anchors container. Thread shape is `Map<ThreadId,Map<{start:number[],end:number[],question?:QuestionId,state:"open"|"resolved"|"detached",messages:MovableList<{by,at:number,text:string}>}>>`. Encode start/end using the existing cursor byte-array convention. Add ThreadId/QuestionId/RequestId types to pure exports.
- [ ] Thread author accepts existing human/agent/model variants plus `{kind:"guest",name:string,linkId:string}`. Thread ops take the inputs in Task 2; adapters supply attribution as context, not a permission-bearing input (decision in this plan): studio human, CLI/MCP `{kind:"agent",name:"cli"|"mcp"}`, review `{kind:"agent",name:"model"}`. Keep guest writes unavailable until P2; adding its data variant grants no capability. Test attribution cannot authorize direct document edits.
- [ ] Reuse `select`, `anchors`, `interval` in `model/selection.ts`, which alternatives already use. Select a unique quote in the retained base, then encode cursors on its first/last characters with Left/Right sides. Open against that base and resolve in current history. Duplicate quotes fail AmbiguousQuote; empty quote fails validation. Do not search for a nearby replacement after deletion.
- [ ] Authority normalization after imported typing and model ops marks an empty/reversed interval detached, retaining messages/question; partial deletions stay anchored. Detached is terminal and stays detached on later insertions (decision in this plan). Resolved threads whose anchor vanishes also detach because the shape has one state (decision in this plan). Never borrow alternatives' dissolution/stashing behavior for comments. Replies append to nested MovableList, resolve changes state, neither deletes a thread.
- [ ] Restrict mutation to model code and authority transactions, import editor history unchanged, then normalize separately. Extend existing inverse/session handling for these ops without whole-document rollback. Test mixed threads/mdx imports through the corrected `editor/sync.ts` binding and restart durability. Assert clean/full read projections and exported MDX contain neither threads nor requests, independent of comment text.

### Task 3 — Extend the existing provider with review mode

- [ ] Keep provider endpoint/model/tokenRef in the existing device `$COMPOSED_HOME/config.json` rewrite configuration. `rewrite.ts` currently builds the JSON system/user messages and HTTP validation; `ops/registry.ts` performRewrite captures selection, releases the queue for HTTP and commits through propose. Reuse that transport, cancellation and receipt discipline; add a review mode, not a package or second provider setting.
- [ ] Capture `{base,text,reader,medium,budget,ruleset,questions:{id,text}[]}` under the authority queue. Text is the clean projection; ruleset is plan 13's effective rules including disabled entries. Send all of it as data in the review brief, directing the model to answer the questions without nagging about disabled rules. Test exact captured brief with the HTTP double, including meta-only hellotimber context and dim exclusion.
- [ ] Validate response `{answers:{question:QuestionId,text:string,notes:{quote:string,text:string}[],rewrites:{quote:string,versions:string[]}[]}[]}` (decision in this plan). Require one answer for each known question, reject duplicates/unknown questions, empty quotes/versions and malformed JSON before any answer-derived mutation. Permit no notes/rewrites. Reuse provider response budget/timeouts and do not log briefs/tokens.
- [ ] After HTTP, re-enter authority queue. Resolve note/rewrite quotes in the captured clean base using the existing selection mapping. Each note opens a thread with question and `{kind:"agent",name:"model"}`; a now-deleted target creates a detached thread. Each suggested rewrite calls the existing model `propose` function with captured selection and model attribution, obtaining an alternative or detached stash result. Never insert rewrite text into MDX or leave a rewrite only in thread text.
- [ ] Commit answers, new threads and proposals atomically after validating all selections; invalid/ambiguous quotes fail visibly without partial results. Preserve concurrent human edits and let existing proposal overlap/edge rules apply. Persist failures as failed request state; retrying a failed review uses a new feedback request (decision in this plan). A pending request found after authority restart becomes failed with a retry instruction rather than silently calling the provider again (decision in this plan).
- [ ] Persist the initial request and final result with the existing receipt/journal machinery: use the caller receipt to replay the same request ID/result, and a stable internal completion identity derived from that request for final commit (decision in this plan). Duplicate in-flight requests share one provider call. Capture then await outside the queue, including socket handling in studio.ts, so typing continues. Cancellation/disconnect ignores late output; if cancellation precedes answer commit mark failed, while a committed answer wins a late cancellation. Do not add feedback.cancel or another op. Cover crash windows before/after both commits and lost acknowledgements.

HTTP-double cases cover complete answers, note/rewrite landing, source unchanged, disabled-rule brief, concurrent typing/deletion, bad JSON/quotes, 401/timeout/cancel, in-flight duplicates, replay and restart.
