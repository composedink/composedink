### Task 2 — Add file editing and sustained preview

- [x] `composed component edit <id> <directory>` requires studio, auto-starting `composed studio --headless` if absent; never own inline. It checks out files plus per-file base metadata and watches local saves. Import saved changes through component.write at the recorded base, never overwrite latest. Authority imports trigger a reverse checkout update only when the local file still equals its prior checked-out hash; preserve unresolved local changes and report a conflict. Own write events must not loop.
- [x] Extend 01's studio-owned component-change/rebuild/evaluate/re-export subscription with file sync and last-good retention. `composed preview` requires studio (auto-start headless), never inline. Studio subscribes to post/component changes and regenerates preview MDX/lock only after build, prop validation and fallback evaluation succeed. Code, fallback and dependency changes produce new immutable dev versions; no mutable overwrite of a loaded remote name.
- [x] Lock import invalidates the example MDX module; reload the page rather than trying in-place module replacement. Failed check/build/evaluation keeps last good pair and displays diagnostics in CLI/studio. Prose-only changes also re-export. Studio owns port 4848 and subscription lifetime; a detached CLI does not stop the service. Studio never loads remotes in its origin; use the blog/example dev origin (P3 adds editor usercontent). No fs.watch-based multiwriter store.
